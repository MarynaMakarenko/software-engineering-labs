## 5. Оцінювання відповідності (M1)

Оцінка 0–100 = сума 4 критеріїв (патерн Strategy, інтерфейс `MatchCriterion`):
- **Посада** (55): бажана посада людини або посада з історії роботи збігається з посадою вакансії (без урахування регістру; назва однієї посади входить в іншу цілими словами) → 55; спільне слово довжиною ≥ 4 символи → 25; інакше 0.
- **Зарплата** (15): бажана зарплата не вказана або ≤ зарплати вакансії → 15; ≤ 115 % → 7; інакше 0.
- **Освіта** (15): найвищий рівень освіти людини ≥ вимоги (або вимоги немає) → 15; інакше 0.
- **Досвід** (15): сумарний стаж (роки, з історії роботи; поточний запис — до сьогодні) ≥ вимоги → 15; ≥ половини вимоги → 7; інакше 0.

Без збігу посади оцінка ≤ 45, тобто за порогу 50 % у списку лише люди зі збігом посади (повним або частковим).
Враховуються лише люди зі статусом «шукає роботу» (для підбору кандидатів) і лише відкриті вакансії (для підбору вакансій).
Поріг за замовчуванням — 50 %; «часткові збіги» — 25 %; користувач може задати мін. оцінку 0–100 (ціле).
Результат сортується за спаданням оцінки, далі за прізвищем / посадою.

## 6. Критичний варіант R2 «Підбір кандидатів на вакансію» — повний опис

Актор: Рекрутер. Мета: отримати впорядкований список відповідних резюме і запропонувати кандидата(ів) компанії.
Передумови: Рекрутер увійшов у застосунок (U1); у БД є щонайменше одна відкрита вакансія.
Основний потік:
1. Рекрутер відкриває «Панель рекрутера» і в таблиці відкритих вакансій натискає «Підібрати кандидатів» біля вакансії (або те саме з картки компанії).
2. Застосунок відображає сторінку «Підбір кандидатів»: параметри вакансії (компанія, посада, зарплата, мін. освіта, мін. досвід, місто) та поле «Мін. оцінка, %» (50).
3. Застосунок обчислює оцінку відповідності (M1) для кожного резюме зі статусом «шукає роботу» і показує ті, де оцінка ≥ 50 %, за спаданням оцінки: ПІБ, бажана посада, бажана зарплата, освіта, стаж, оцінка (%) і складові оцінки.
4. Рекрутер натискає ПІБ кандидата — застосунок відкриває картку людини з історією роботи (R4); Рекрутер повертається до списку.
5. Рекрутер натискає «Запропонувати» біля кандидата; застосунок показує форму з полем «Коментар для компанії» (необов'язкове, ≤ 500 символів).
6. Рекрутер вводить коментар і натискає «Підтвердити».
7. Застосунок створює кандидатуру (статус «Нова», джерело «Рекрутер»), показує повідомлення «Кандидатуру <ПІБ> запропоновано на вакансію <посада> (<компанія>)», у рядку кандидата замість кнопки — позначка «Запропоновано: Нова».
8. Рекрутер повторює кроки 4–7 для інших кандидатів або повертається на панель.

Альтернативні потоки:
- A1 (крок 3) Немає кандидатів з оцінкою ≥ порогу → повідомлення «Немає кандидатів з оцінкою від N %» і кнопка «Показати часткові збіги (від 25 %)»; Рекрутер натискає — застосунок показує список з порогом 25 %.
- A2 (крок 2–3) Рекрутер змінює «Мін. оцінка, %» і натискає «Оновити» → перерахунок. Якщо значення не ціле або поза 0–100 → діагностичне повідомлення (3 частини), поріг лишається попереднім.
- A3 (крок 5) Кандидата вже запропоновано на цю вакансію або він сам відгукнувся → кнопки «Запропонувати» немає, показано статус наявної кандидатури; якщо повторний запит все ж надійшов (подвійне натискання, інша вкладка) → повідомлення «Кандидатура вже існує», дублікат не створюється.
- A4 (крок 1–2) Вакансія закрита → повідомлення «Вакансію закрито — підбір недоступний», посилання «До відкритих вакансій».
- A5 (крок 6) Коментар > 500 символів → діагностичне повідомлення, введений текст збережено у формі, кандидатура не створюється.
- A6 (крок 6) Рекрутер натискає «Скасувати» → форма закривається, змін немає.
- A7 (крок 1–7) Вакансію або людину видалено іншим користувачем → сторінка «404 — Не знайдено» з посиланням на панель.
Спец. вимоги: підбір для бази до 10 000 резюме виконується ≤ 2 с; оцінка пояснюється складовими (прозорість); таблиця доступна з клавіатури, контраст ≥ 4.5:1.
Постумови: у БД додано рівно одну кандидатуру на кожне підтвердження або БД не змінено; дані резюме й вакансії не змінюються.
Точки розширення: крок 4 — «Перегляд історії роботи людини» (R4).

## 8. Технології

Java 21 (збирання JDK 21+, `--release 21`), Spring Boot 3.5 (Spring MVC, Spring Security, Spring Data JPA/Hibernate, Bean Validation), Thymeleaf, HTML5/CSS3 (власна таблиця стилів, адаптивна верстка), мінімум JavaScript.
СКБД: H2 2.x у файловому режимі з режимом сумісності PostgreSQL (на ноутбуці), міграції Flyway `V1__schema.sql` (схема) + `V2__seed.sql` (первинні дані); для хостингу — PostgreSQL 16 (той самий DDL).
Тести: JUnit 5, Mockito, Spring MockMvc (інтеграційні), Playwright (функціональні UI-тести у Chrome). Збирання — Maven. IDE — IntelliJ IDEA. Git.
Архітектурні стилі: MVC, багатошарова архітектура (Presentation → Service → Repository → Domain). GoF: Strategy (критерії відповідності), Facade (MatchingService), Template Method (базові CRUD-контролери — не використано), DTO/Form Object. GRASP: Controller, Information Expert, Creator, Low Coupling, High Cohesion, Pure Fabrication (MatchingService).
Безпека: BCrypt, ролі, CSRF-токени, параметризовані запити JPA (захист від SQL-ін'єкцій), екранування Thymeleaf (XSS), заголовки безпеки Spring Security.

## 9. Нефункціональні — числа
